AI agent security

Did this change make the agent more dangerous?

ChangeFence compares a known-safe version of an AI agent with a proposed new version and finds dangerous capabilities that appeared because of the change.

Try one exampleACME PROCUREMENT

Critical security regression

Procurement can now indirectly reach payment execution.

The new version never directly gives Procurement permission to make a payment. But because Procurement can delegate to Finance, and Finance can execute payments, the combined system creates a new authority path.

Procurement Agent
↓ NEW: delegates to Finance
Finance Agent
↓
Payment API · payment.execute
In plain English: nobody wrote “let Procurement make payments,” but the new connection makes that outcome possible. ChangeFence catches the consequence of the change, not just the changed line of code.

What ChangeFence does

The product is intentionally simple: compare what the agent could do before with what it can do after the change.

01 · COMPARE

Before vs after

Read the trusted agent configuration and the proposed release.

02 · FIND

New capabilities

Follow tools and agent-to-agent delegation to find newly reachable actions.

03 · GATE

Allow or block

Fail the release when a new capability violates a security rule.

Optional local AI red team

A local model through Ollama can propose attack ideas privately on your machine. ChangeFence then independently verifies whether those ideas are actually possible. The AI proposes; the deterministic engine decides.
